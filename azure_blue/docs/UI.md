# UI

1画面（`frontend/index.html`）。スマホ縦持ち前提。

デザインは azureblue.shop に合わせる: #005B9D / #00375F / 背景 #F7F7F7、見出しは明朝・大文字ラテン・字間広め、細い罫線のみ・影なし・角丸なし。説明文は置かない。タイトルは「納品書 ›› 販売王」（店名は入れない）。

- 下部固定: SCAN（カメラ起動・複数選択可）／CSV
- 撮影ごとに納品書カードが追加され、裏で読み取りが並行で走る
- 解析中は写真の上をスキャンラインが往復し、明細部分はスケルトン表示（ANALYZING）
- カード: 番号・仕入先（プルダウン）・伝票日付／明細（ワイン名、読取原文、単価○円 × 数量○本 ＝ 金額○円）
- ワイン名の右に小さな「変更」バッジ。押すと全画面の選択画面（検索ワードを入れるまで候補は出さない。検索欄は上部固定、右上×で閉じる。キーボードや絞り込みで位置が動かない）。
- マスタに当たらない明細は読み取った品名のまま、行全体を薄い青（#e8f1f8）でハイライトし「新規登録」「変更」の2ボタン。新規登録 → その1件の登録画面（商品名＝読取値、フリガナ・略称・イニシャル＝AI下書き、上代・標準売値・売値1＝手入力、原単価は表示のみ。下部は 戻る／登録）→ 登録でDBに入り明細へ戻る
- 12の倍数でない納品書はカードの枠全体を赤くし、赤帯に「無視」ボタン（押すと赤を解除。CSVは止めない）
- 警告（黄色）: 印字の税抜合計と読取金額の合計が不一致・仕入先未選択（数量計・単価×数量の検算は廃止）
- トークン: 画面には出さない（サーバーログ `journalctl -u azure-blue | grep usage` で確認）
- PWA: manifest・sw.js（素通し）・アイコン（アズールブルーのワイングラス）。入力は16px以上でiOSのズームを防ぐ。safe-area対応
- 仕入先プルダウンの「＋ 仕入先を追加」→ 下からフォーム（コード・名前。名前は読取値を下書き）→ 保存するとその仕入先が選ばれる
- 明細の右端 × で行を削除（CSV・検算から外れる）
- ヘッダ右端にログアウト（/gate/logout → login.html）
- 専用ログイン画面 `frontend/login.html`（白地・ワイングラス・明朝タイトル・下線入力・青のLOGIN）。demo側の未ログイン時はここへ302
- 納品書カード自体の削除ボタンは置かない（行単位の×のみ）
- 下部: SCAN（captureなし。スマホ標準のメニューで「撮影／写真ライブラリ（複数可）／ファイル」を選ぶ）／CSV・次へ
- 金額欄（単価・金額・上代・標準売値・売値1）はカンマ区切り表示。`x-yen` ディレクティブで、入力中はカンマなし・離れるとカンマ付き、値は数値で保持
- 「新規登録」の行が1つでも残っている間はCSVを押せない。全部なくなるとCSVで（新商品があれば）商品台帳→仕入伝票の2ファイル
