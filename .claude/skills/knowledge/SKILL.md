# knowledge

坂本の思想・考え方・現場の学びを貯めた引き出し。中身は PocketBase の `knowledge` テーブル（id / category / content）。

## カテゴリー

| カテゴリー | 入るもの |
|---|---|
| 営業 | ヒアリング・提案・顧客との話し方、伝え方 |
| 契約 | 知財・権利・契約条件の線引き |
| 開発思想 | システムづくりの考え方（例：機能は減らす方がいい） |
| IT知識 | 調べれば出てくる技術的な事実だけ。考え方は開発思想へ |
| 名言 | 生き方・仕事観・自分についての気づき |

## 道具

```
python3 /root/common/knowledge/kb.py list [カテゴリー]
python3 /root/common/knowledge/kb.py add <カテゴリー> <中身>
python3 /root/common/knowledge/kb.py add-many < items.json   # [{"category": ..., "content": ...}]
python3 /root/common/knowledge/kb.py update <id> [--category X] [--content Y]
python3 /root/common/knowledge/kb.py delete <id>
```

- 検索機能はない。`list` で全件を読み、意味で選ぶ。
- 認証情報（`/root/common/.env` の PB_EMAIL / PB_PASSWORD）は絶対に表示しない。

## 1. 引き出す（質問に答える）

1. `list` で全件を読む。
2. 問いに関係するものを、カテゴリーをまたいで選ぶ。言葉が一致しなくても意味が近ければ含める。
3. 出力はデフォルトで箇条書き。カテゴリーを見出しにし、関係の強い順に並べる。表を頼まれたら「カテゴリー｜内容」の表にする。
4. 中身は原文のまま引用する。言い換えない・要約しない。
5. 該当がなければ「蓄積の中には該当なし」とはっきり言う。蓄積にない内容を、坂本の考えとして作らない。
6. 必要なら一覧のあとに、問いへの当てはめを2〜3行だけ添える。

## 2. 議事録・文字起こし・対話から探す

渡されたテキストを読み、次の2つを分けて出す。

- **既存のノウハウが表れている箇所**：その発言の引用と、対応する既存の中身。
- **新しい候補**：坂本自身の判断・原則・使える言い回しのうち、まだ蓄積にないもの。顧客側の事情や一回限りの事実は除く。

新しい候補のルール:

- 番号付きで、カテゴリー別に並べる。
- 中身はテキスト中の言葉をそのまま切り出す。整えたり要約したりしない。
- 既存と同じくらい似ているものは出さない（片方だけ残す方針）。近いが別物なら「既存の〇〇と近い」と添える。
- **登録はしない**。「1, 3, 5 を登録」「2 は契約で」のように OK をもらってから `add-many` で入れる。

## 3. 登録・修正・削除

- 「残して」「登録して」と言われたら、カテゴリーを提案して OK をもらってから `add`。
- 中身は原文そのまま。誤字や話し言葉も直さない。
- 似たものがすでにあれば、登録せずにそれを示す。
- 修正・削除は `list` で対象と id を特定し、内容を見せて確認してから `update` / `delete`。
